# Optimal Foundry: architecture and contracts

One client-side Foundry module (v14 minimum, verified 14.370). No server code: everything runs in the browser. One session of the active GM coordinates (`isCoordinator()`, see Core contracts). Module id `optimal-foundry`. Requires `lib-wrapper` (no fallback without it).

The Foundry source this targets lives at `/Applications/Foundry Virtual Tabletop.app/Contents/Resources/app` (`client/` unminified ESM, `common/`, `dist/` minified server). Read it instead of guessing APIs.

## Core contracts

- **Setting changes.** Every setting's `onChange` fires `optimal-foundry.settingChanged(key, value, options, userId)` (bare key, e.g. `"library"`). Listen to that, never `updateSetting`/`clientSettingChanged`: the first write of a world setting is a Setting *create*, which `updateSetting` misses, and client settings never fire it. The three profile-controlled settings (`maxConcurrentRequests`, `preloadSharePct`, `staggerJoin`) are greyed out in the settings form unless the profile is "custom". `effectiveNetwork().p2p` is just `p2pEnabled`.
- **Socket.** Envelope `{t, p, from, to?, rid?, re?, err?}` on `module.optimal-foundry`; the server-supplied sender id overrides `from`. A broadcast is emitted with no options argument at all: socket.io turns a trailing `undefined` into `null`, and the server's `{recipients} = {}` destructuring throws on `null`, which silently drops the message. A handler's return value answers a `request`; `undefined` sends no answer (passive sessions use this so they never race the coordinator). Request ids carry the session id, and a reply is accepted only from the user the request went to (`senderId === to`); a forged reply leaves the real one pending.
- **Coordinator session lock.** `game.users.activeGM` picks the user; a user may have several sessions (desktop app plus a browser tab), and messages addressed to the user reach all of them. Each GM session sends `MSG.COORD_BEAT {sid, startedAt}` to its own user at ready and every 10 s, and answers a new session's first beat at once. A closing session sends `{sid, bye: true}` on `pagehide`; a crashed one expires after 75 s (longer than Chrome's 1-minute timer alignment for hidden tabs, so a backgrounded coordinator is never taken for dead). `isCoordinator()` is true only on the active GM's oldest live session (by `startedAt`, then `sid`). `optimal-foundry.coordinatorChanged(bool)` fires when that changes (beats, expiry, any GM `userConnected`). Right after `ready` a new GM tab counts as coordinator until the older tab's answer arrives (one round trip); everything that acts on it is debounced or delayed past that.
- **Batched library writes.** The library is one world setting, so each write sends the whole object to every client. Every write of a client runs on one promise chain that re-reads the library inside the chain. `putEntries(entries, {now})` queues partial entries (merged field by field) and writes 20 s after the last call, at most 60 s after the first queued entry; `{now: true}` writes at once and its promise settles with that write. Await it only when the entry must be durable (a `done` entry right before references are re-pointed); otherwise `.catch` it. `removeEntries` drops queued writes for those keys, then writes on the same chain. `flushLibrary()` writes the queue now and resolves when every write has settled (never rejects; used on pause, loop end, undo and `beforeunload`). `getLibrary()`/`getEntry()` return the merged view: stored value, then pending writes, then the queue. `findByOptimized` indexes only `done` entries; `optimal-foundry.libraryChanged` fires after each re-index (on `settingChanged("library")`).

## Product rules (from the owner)

1. Every upload is optimized before it reaches the server; only the optimized file is stored. If the uploading client cannot encode (no WebCodecs / WebP canvas encoder), the original is uploaded and the GM converts it in the background (`MSG.CONVERT_REQUEST`).
2. Existing world assets are optimized in the background by the coordinating GM session, the way the GM chose: automatically, only what they approved (review first, the default), or not at all. Nothing converts existing files before a GM finishes the welcome screen. The backfill never deletes or overwrites originals; documents are re-pointed to the optimized copy, and every rewrite is undoable from the library until the GM empties the original in the Cleanup tab (see `cleanup.mjs`).
3. **Keep resolution by default** (`keepResolution: true`): only codec/bitrate/quality change. Resizing happens only when the GM turns it off (`maxImageSide`, `maxVideoHeight`). WebP cannot exceed 16383 px per side: such images are skipped (`tooLarge`) when keeping resolution.
4. Players use Chrome/Edge/Firefox only. VP9 alpha and Ogg Opus are fine.
5. Everything is configurable. Nothing owner-specific is hardcoded; the module is shared with friends who may have no domain, no CDN and no Service-Worker header.
6. UI text in Brazilian Portuguese (plain, direct) with English fallback.
7. Preloading is automatic: the GM never has to mark scenes (marking only puts a scene first). The GM can keep a small floating tracker of the module's state over the canvas; players never see it.

## Formats and naming

- Image → WebP (`OffscreenCanvas.convertToBlob({type:"image/webp", quality})`), verified by `blob.type`. Lossless sources (PNG, static GIF, BMP, TIFF) are also encoded lossless (quality 1) and the lossless file wins unless it is more than 15% larger than the lossy one: flat map art grows 2-3× as lossy WebP but shrinks 80-90% lossless. SVG never touched. Already WebP/AVIF → skip.
- Static GIF → WebP. Animated GIF: on upload kept as-is. In backfill, converted to WebM VP9 with alpha only if every reference is a texture/video-capable field and `convertAnimatedGif` is on; otherwise `animatedGifImageField`.
- Video → WebM VP9 via Mediabunny `Conversion`. Target bitrate (`videoBitrate`): bits per pixel from `videoQuality` anchored at 1080p30, scaled by (pixels/1080p)^0.75 × (fps/30)^0.5, capped at 70% of the source's video bitrate (a leaner target would only inflate the file), clamped to 0.5–20 Mbps (64 kbps floor for animated GIF/APNG). Audio track → Opus unless `videoStripAudio`. Audio → Ogg Opus. Ogg/Opus input and MP3 below `skipMp3BelowKbps` are skipped.
- The kind comes from the references when known (`optimizeUrl(path, {kind})`, e.g. an audio-only `.webm`), else from the extension.
- Kept original when the output is not at least `minSavingsPct` smaller (`noSavings`).
- Output name `<sanitized-stem>.of-<first 8 hex of SHA-256(output)>.<ext>`. Content-hashed names are never reused for different bytes, which is what makes the year-long CDN cache safe.
- Output location: same folder as the original; originals under `modules/`, `systems/` or outside the `data` source go to `optimal-foundry/<original dir>/` at the Data root (`naming.outputLocation` / `ensureDirectory`).

## Media (`scripts/media/`)

- `converter.mjs`: `canConvert(kind)` (memoized probe); `optimizeFile(file, {name, kind?, referenceKinds?, signal?, onProgress?})`; `optimizeUrl(path, {kind?, referenceKinds?, signal?, onProgress?})` (no-store fetch, ranged reads for video/audio). `OptimizeResult = {status: "done"|"skipped"|"failed", kind, file?, sha256?, bytes?, originalBytes, reason?}`.
- `upload-hook.mjs`: libWrapper `WRAPPER` on the static `FilePicker.upload`, re-entry guarded by a WeakSet; `skipUploadHook(file)` adds a module-internal file (the cleanup's empty files) to it. Converts when `optimizeUploads` and capable, uploads the optimized file, then registers it (coordinator → `putEntries`, anyone else → `MSG.REGISTER_OPTIMIZED`). Such entries are keyed by the stored optimized path itself (`original === optimized`, `uploadedName`). A conversion shows a progress notice after 1.5 s; clicking it, or 90 s without progress, uploads the original instead. Success toasts of a multi-file drop merge into one. Optimized files above 95 MB on a non-local origin warn about the tunnel's 100 MB limit.
- `references.mjs`: `installRewriteGuards()` (every client, at init) keeps core's PlaylistSound#_onUpdate from throwing "audio not unlocked" when a rewrite changes a track's `path` on a client that has not unlocked audio yet (the Sound is created lazily once it unlocks). `collectReferences({includeCompendia, signal, unread}) → Map<path, Ref[]>` (`unread = {external: Set, vector: Set}`, optional, collects media on other hosts and SVG that are dropped) walks every world document by schema (`FilePathField` kinds from categories, `HTMLField` img/video/audio/source/a, Markdown `![](…)`/`[](…)` targets, `TypeDataField` system models, plain `system`/`flags` strings with media extensions). Scene levels hold background/foreground/fog (`Scene#background` is a shim, never written). `collectDocumentReferences(doc, {children})` does the same for one document. `rewriteReferences(map, {refs, protect}) → {updated, skipped, failed, deferred, failedFrom}` updates each document once, reads the value back, and returns protected refs untouched in `deferred`.
- `cleanup.mjs`: `findCleanupCandidates({signal}) → {candidates, inUse, outsideWorld, brokenCopy, gone}`, `emptyOriginals(items, {signal, onProgress}) → {emptied, kept: [{original, reason}], freedBytes}`; both coordinator only. Foundry's server cannot delete (manageFiles only browses, creates directories and configures paths), but `Files.upload` sets `overwrite` when `UPLOADABLE_FILE_EXTENSIONS[ext]` is in `MEDIA_MIME_TYPES` and never inspects content, and express-fileupload keeps a named 0-byte part. So the cleanup empties an original by uploading `new File([], <same name>)` into its folder through `FilePicker.upload` (marked with `skipUploadHook()` so the upload hook does not convert it). Eligible: a `done` entry (not `cleaned`, original ≠ optimized) whose raw key (never re-normalized: that would cut a decoded `#`) is under `worlds/<this world>/`, has no `#`, `?`, empty, `.` or `..` segment, and an overwritable extension. "Used" is a text search, not the reference walker: the `_source` JSON of every world collection (ChatMessage, Macro and Setting included; the module's own settings and FogExploration excluded) and every world compendium, NFC and lowercase, looking for the key as stored, `encodeSegments`, `encodeURI` and with `&amp;`. Any mention keeps the file; other worlds are not searched. Analysis also needs HEAD 200 with content and the optimized copy's HEAD size equal to `bytes`; an original at 404 or 0 bytes is marked `cleaned`. `emptyOriginals` holds backfill's `beginCleanup()`/`endCleanup()` section (undo refuses to start while it is held, and the cleanup refuses while an undo runs) and works in groups of 10: search the documents again; check each item (eligible, unmentioned, HEAD with Content-Length > 0, `fingerprintOf` equal to `source` or else size equal to `originalBytes`, optimized copy downloaded and matched against `bytes` and `sha256`); write `cleaned` for the checked items in one durable write BEFORE any upload (a failed write empties nothing); upload; then HEAD each original: 0 bytes means emptied, the old fingerprint means `uploadFailed` and anything else means `changed` (both get the mark cleared again), and an unreadable file stays marked as `uncertain`. Emptied entries keep `status: "done"`, so `processItem` re-points any later reference to the optimized copy (it treats `cleaned`, or an original HEAD at 0 bytes, as final), and `undo()` keeps `cleaned` entries and originals at 0 bytes.
- `backfill.mjs`: `initBackfill()`, `scan()`, `start()`, `pause()`, `isRunning()`, `backfillStatus()` (also `review` count, `mode`, `waitingWelcome`), `reviewList()`, `approve(originals?)`, `decline(originals)`, `undo(originals?)`, `retry(originals)`, `fingerprintOf(headers)` (the `source` fingerprint: ETag, else Last-Modified|length). Coordinator only, one conversion at a time.
  - **Gating.** Before each item it waits (up to 120 s) while this canvas is loading or `playersBusy()` (a remote player joining, drawing a scene or loading urgently), then for an idle callback. `scan`/`start` refuse when `mediaEnabled` is off, and `start` when `backfillMode` is "off" or before `welcomeDone`. `start` scans when the queue is empty or no scan ran this session yet (a document edited before the first scan queues one item). `kick()` restarts the loop when work arrived while it was finishing, and a loop that stops because another session took over clears `state.active`, so the auto-start runs again when the role comes back. Start/Pause in the dashboard also write `backfillPaused`, so a pause survives a reload. Auto-start (30 s after ready, 5 s after the welcome screen or a mode change) and starts from new references need `autoAllowed()`: media on, mode not "off", not paused (persisted or this session), and `welcomeDone`. When only the pause blocks it, the timer still runs one scan (review list and scan table; nothing converts). `backfillStatus().paused` includes the persisted `backfillPaused`.
  - **Modes** (`backfillMode`: auto | review | off, default review). `scan()` classifies as before, then `splitForReview`: "auto" queues everything; "review" keeps conversions whose original is not in `reviewApproved` in `state.review` (rewrites of converted files still run); "off" queues nothing (no rewrites either). New references found by the document hooks follow the same rule. `reviewList()` → `[{original, kind, refs: uuid[]}]`; `approve(originals?)` (all when omitted) writes `reviewApproved` before anything converts, moves the items to the queue, clears `backfillPaused` and starts (or kicks a running worker; before the welcome screen the approval is only saved); `decline(originals)` writes `{status: "skipped", reason: "declined"}` (durable) only over no entry or a failed one, so no scan offers them again until Retry forgets the entry. Every `reviewApproved` write goes through one promise chain that recomputes the list from the last write (an approval and a prune never overwrite each other); each scan prunes approvals whose original has a final entry (done, skipped, failed ×3). A mode change stops the worker (a player's request finishes), waits for a scan already running, rescans and auto-starts if allowed. Right before working on a non-urgent item, `held()` checks the mode and approvals again: "off" drops it, an unapproved conversion in review mode goes back to `state.review` (so a stale queue never converts without approval). A converted original whose source changed on disk is a new conversion and needs approval again in review mode. `reviewList()` drops items that got a final entry meanwhile (a player's request); `onConvertRequest` removes its file from the review list. Retry in "off" does not re-optimize restored entries (nothing would re-point them); after a retry an idle, allowed worker starts. `library.mjs` `willConvert(path)` (true in auto, in review only for approved originals, false when off, paused, before the welcome screen or with media off) tells the preload whether to leave an unconverted original out of the queue; `isApproved`/`forgetApproved` keep a cached Set of `reviewApproved`.
  - **Queue.** Candidates are referenced media that are not optimized, not already-optimal formats, and not `skipped` or `failed` ×3. Order: rewrites first, earlier failures last, then `preloadRank()` (the preload queue: what players are viewing, the active scene's neighbours, …), then kind, reference count, name. It re-sorts 2 s after a `nextScenes` or active-scene change. Documents created or edited mid-session (imports, drags) are scanned by hooks (debounced per uuid): references to converted files are re-pointed at once, new media is queued.
  - **Item.** HEAD the original (its ETag, or Last-Modified|length, is the `source` fingerprint; 404 → `skipped/missing` with up to 10 referencing uuids in `refs`). A `done` entry whose source changed is converted again. Convert → upload → `putEntries(done, {now})` awaited → re-point. Re-pointing is batched (20 originals, or when the loop ends) into one `rewriteReferences` call, and is refused (`notPersisted`) unless the persisted `done` entry carries that optimized path. `protectActiveScene` defers refs in scenes someone is viewing and in playing sounds; they retry on `canvasReady`, sound stop, scene change and every 60 s. Player requests and new references run as urgent items, even while paused.
  - **Crash marker.** `localStorage["optimal-foundry.backfillCurrent"]` (world id + path) is set before each conversion and cleared after it and on `pagehide`. A marker found at the next scan records `failed/interrupted` with attempts+1, so a file that crashes the renderer is retried at most 3 times.
  - **Undo / retry.** `undo` waits for the loop, flushes the library, re-points optimized → original, and marks those entries `{status: "skipped", reason: "restored"}` in one write, keeping `optimized`; nothing converts them again until `retry`. Entries whose original is missing, `cleaned` or at 0 bytes are kept, and undo refuses to start while the cleanup runs. It restarts the backfill if it was running. `retry(originals)` makes restored entries `done` again (re-pointed at once, no encode) and forgets skipped/failed ones so the next scan converts them; it returns the number of entries affected.
  - `backfillStatus() = {running, paused, phase: "idle"|"scanning"|"converting"|"rewriting", current?: {original, kind, progress, urgent}, queued, run: {done, skipped, failed}, deferred, lastError?: {path?, reason, detail?}}`. `scan()` resolves `{paths, convert, rewrite, kinds: {image, audio, video}}` or `null`. Each scan also stores the `scanReport` world setting: `{at, total, byOrigin: {world|module|system|core|data|otherWorld: {optimized, light, queued, skipped, failed}}, external, externalExamples, vector, unreadPacks, unreadPackDocuments, includeCompendia}` (`ORIGINS`, `OUTCOMES` exported). Origin comes from the path (mirrored `optimal-foundry/<path>` copies count where their original lives); `light` is a webp/avif/ogg/opus file, which is never queued or recorded. `external` (another host or protocol-relative) and `vector` (SVG) are what `collectReferences({unread})` saw but `mediaKey` drops; `unreadPacks` counts module and system packs (and world packs when `includeCompendia` is off), which are never read because a module update would put their documents back. The dashboard's Media tab renders it as a table per origin with notes.

## Network (`scripts/net/`)

- `scheduler.mjs`: `initScheduler()` at `init`; `networkStatus()`; `schedule(fn, {priority: "urgent"|"preload", url?, signal?})` (`fn({signal, progress})`); `waitForPreloadWindow`, `registerStatusProvider`, `onClientGone`, `askCoordinator`, `tellCoordinator`, `serveCoordinator`, `sceneReady`, `playersBusy()`, `chargeBatch(items, from)`, `adjustBudget`, `loadInBackground(srcs)`, `EST_BYTES`.
  - libWrapper on `TextureLoader.prototype.loadTexture`, `TextureLoader.prototype.load` (caps `maxConcurrent` per client behind a tunnel) and `Sound.prototype._load` count urgent loads. Same-origin textures that fail are retried up to twice after a no-store HEAD probe (a real 4xx gives up). PIXI loads textures on the main thread (`preferWorkers: false`), so they go through the SW and Resource Timing.
  - Idle = no urgent load, canvas not loading, and no foreign resource entry for `idleSeconds`. Every 2 s each client sends `MSG.CLIENT_STATUS {inflight, urgent, bytesPerSec, sceneReady, idle, cacheBytes, joining, local, preload}`.
  - Staggered join: the joiner's turn handshake starts at `setup` (before `ready`) with a raw listener for `JOIN_TURN`, accepted only from the active GM. The coordinator records arrival order on `userConnected` but gives the turn only to joiners that have announced themselves (`joining: true`), one at a time, until `sceneReady` or 20 s. Queue position is shown to the joiner and in the dashboard.
  - `networkStatus() = {profile, cdn, inflight, urgent, preloading, textureRetries, bytesPerSec, idle, sceneReady, joinTurn, enabled, clients?}`; `clients` (coordinator only) `{[userId]: {name, inflight, urgent, bytesPerSec, sceneReady, idle, joining, local, cacheBytes, preload: {done, total}, stale, p2p?, queuePosition?}}`.
- `preload.mjs`: `initPreload()` at ready, `preloadStatus()`, `markNextScene(sceneId, bool)`, `preloadPlan()`, `upcomingReadiness()`, `preloadRank()`, `buildQueue(maxBytes)` (pure over `game`, used by the tests).
  - **Queue (coordinator), automatic.** It always covers everything players may need, most likely first; the token bucket, P2P and the idle window set the pace, and a client above 80% of `cacheQuotaMB` skips tier 3. Tier 0 "now": scenes in `nextScenes` (exclude ignored), the GM's `canvas.scene` when not active, and the `viewedScene` of each connected non-GM user when not active. Tier 1 "probably next": the active scene's other levels (when more than one) and non-hidden AmbientSounds, its whole playlist, playlists with `playing`, the active scene's navigation-bar neighbours (`navigation` scenes by `navOrder`, 2 after and 1 before), scenes holding the destinations of its enabled `teleportToken` behaviors (absolute `Scene.<id>.Region.<id>` uuids only), its folder neighbours in the directory's order (folder `sorting` "a" = name, "m" = `sort`; root uses `game.scenes.sortingMode`), and `preloadInclude`. Tier 2 "this session": the other navigation-bar scenes by distance from the active one, the rest of the playlists linked to tier 0–1 scenes, and `img` + prototype token texture of actors any non-GM user owns. Tier 3 "later": every other scene by `_stats.modifiedTime` desc, the playlists linked to those, every other playlist, and `collectDocumentReferences()` of journals any non-GM user can observe. Each scene brings its visuals, its first track (`playlistSound`, else the playlist's first) and its non-hidden AmbientSounds at its own tier; the rest of its playlist one tier later. Hidden tokens, tiles and other placeables are included (core loads them too); only hidden AmbientSounds are left out. `preloadExclude` and `preloadMaxFileMB` apply. The build also records a plan (`{type: scene|playlist|actors|journals, id, name, tier, reason, files, bytes}`, entries with no new file dropped) that `preloadPlan()` returns with per-tier totals for the dashboard. Items are the paths the documents reference, with size and kind from the library, except that an original already converted but not yet rewritten resolves to its optimized copy, and an original the backfill has not processed yet (no library entry, convertible by name, and `willConvert(path)`: auto mode, or approved in review mode) is left out: warming it would spend the host's upload on a file that stops being used seconds later. The library change after conversion rebuilds the queue. A scene leaves `nextScenes` when it is activated. The queue rebuilds (debounced) on relevant changes, with per-document keys (`WATCHED`: scene content and `navigation`/`navOrder`, Region behaviors, Playlist `playing`, Actor `img`/`prototypeToken`/`ownership`, Journal pages and ownership, User `role`/`character`), on `userConnected`, on setting and coordinator changes, and on library changes at most every 15 s (a running backfill writes it every few seconds). `User#viewedScene` is a client property that fires no hook, so the coordinator compares the connected players' viewed scenes every 3 s. Journal media lists are cached per journal id and dropped by JournalEntry/JournalEntryPage hooks. The walks stop at `MAX_ITEMS` (5000); the per-user "have" sets hold 4× that, so a queue change at the cap does not evict files still queued. `preloadRank()` returns the build's rank: every path the queue walked, as the documents hold it (originals not converted yet included), by first position, which `sortQueue` in the backfill uses. `predecodeNext` decodes the predicted next scene on each client: the first marked scene, else the active scene's next navigation-bar neighbour, else its next folder neighbour.
  - **Batch protocol.** When its preload window is open (idle, join turn, scene drawn), a client asks `MSG.PRELOAD_NEXT {have?, full?}` (`have` only on the first ask, or when the GM answers `needHave` after a hand-over; `full` above 80% of `cacheQuotaMB`, which skips tier 3). The coordinator answers up to 8 items already charged by `chargeBatch` (token bucket at `preloadBytesPerSec`, burst 2 s; a file larger than the burst waits for a full bucket and arrives alone; local/LAN clients and unlimited profiles are free; nothing while a remote player joins, draws or loads urgently) plus `waitMs`, `total`, `done`. The client warms them through `schedule` (at most 3 at once, `priority: "low"`, body drained), then sends one `MSG.PRELOAD_DONE {results: [{src, bytes, est, ok, aborted, reason}]}`; the GM settles the bucket with actual − estimated bytes (aborted items are refunded down to their partial bytes and offered again), adds only ok/tooLarge results to that user's `have`, and keeps 4xx files out for 10 min. The client sleeps `max(250, waitMs)` between batches; `MSG.PRELOAD_WAKE` (sent after every queue change) cuts an empty-queue sleep short. There are no per-file grants.
  - **Aborts.** Any urgent load aborts in-flight preloads, except `.of-` files under SW control (the SW keeps downloading anyway) and fetches past 50%.
  - **`have` sets** live for the session only: in memory on the coordinator (max 5000 per user), and on the client seeded from the SW's Cache Storage when the SW controls the page. Files not served through the SW are capped at 32 MB (larger ones would not stay in the HTTP cache) and reported as `tooLarge`.
  - **Coordinated seeding.** With P2P on and a non-CDN profile, a P2P-eligible optimized file handed to one user is not handed to others for 120 s while nobody but the GM holds it (`holderCount`); the others then get it from that user through the swarm. A client whose remaining items are all reserved gets an empty batch with `waitMs` 2 s and asks again (the fetcher announces about 1 s after finishing); a reservation ends on its TTL, when the fetcher leaves, or when its fetch fails, so nobody starves.
  - A GM on a local origin does not warm anything (loopback saves nothing) but still serves the queue (`preloadStatus().running === false`). `preloadOnThisDevice` (client setting) opts a device out.
  - **Pre-decode** (`predecodeNext`, off by default): once every image of the predicted next scene (see above) is warmed, decode them into Foundry's texture cache in the background (`loadInBackground`, 2 at a time, no urgent accounting), only on performance mode MED or higher and below 70% of core's texture memory limit.
  - `preloadStatus() = {enabled, running, queueLength, current?, done, total, paused}`. `upcomingReadiness() = {[userId]: {have, total, bytesLeft}}` for the tier 0–1 items (coordinator only).
- `cdn.mjs`: `detectCdn({force})` (coordinator, at ready): HEAD (fallback 1-byte Range GET) a media file twice and read `cf-cache-status`; caching CDN when the header exists and is not `DYNAMIC`/`BYPASS`. Stores `{cdn, status, origin, url?, by?, checkedAt}` in `cdnStatus` (unchanged results rewritten at most hourly). A GM on a local origin cannot see the edge: it asks a player to probe (`net.cdnProbe`) on that player's first `CLIENT_STATUS` reporting a remote origin and a drawn scene (so its handler exists and it sees the edge; a fixed delay after `userConnected` timed out on slow joins and picked local-origin players), and keeps a remote result for 7 days; `force` (the dashboard button) asks again now and never stores "local". `isLocalOrigin(hostname?)`, `initCdnResponder()`.

## Service Worker and P2P (`scripts/p2p/`, `sw.js`)

- `sw.js` (self-contained classic script, `VERSION` must equal `SW_VERSION` in `sw-client.mjs`). Registered with scope `/` (route root): first an existing registration's script, then the Data-root copy `/optimal-foundry-sw.js` (no header needed), then `/modules/optimal-foundry/sw.js` (needs `Service-Worker-Allowed: /`).
  - Intercepts only same-origin GET requests for media extensions; `/socket.io`, `/upload`, `/setup`, `/join`, `/auth` and everything else pass through.
  - `.of-` paths (immutable): Cache Storage `optimal-foundry-v1` first. On a whole-body miss, ask the controlling page `{type: "p2p-get", url, id}` over a MessageChannel when the page enabled P2P; the page acknowledges at once (the SW gives it 1.5 s), then pings progress, then answers with a verified Blob or `null`; the SW gives up after `p2pTimeoutSec` without progress. Otherwise one network fetch (default cache mode, so the HTTP cache may answer) streams to the requester and stores the full 200 response. LRU eviction against `cacheQuotaMB` (metadata in IndexedDB, reconciled on the first config message); the page is told `cached`/`evicted` so the swarm announces it.
  - Range requests: a hit is sliced from the stored body (206). A miss goes straight to the network with the original Range header, never waits for P2P or a download in flight, and is not stored; audio/video element loads never wait for P2P either, so media streaming starts at once. Whole files reach the cache through preload.
  - Mutable media (any other media path; Foundry overwrites same-name files silently): stored in the same cache, and every hit is revalidated with the stored ETag/Last-Modified at most once per 30 s (304 serves the copy, 200 replaces it, 404/410 drops it, network error or 5xx serves the copy). Never fetched over P2P. The config field `revalidateMutable` (default true) turns it off and drops those copies.
  - Messages from the page: `config {p2p, timeoutMs, quotaBytes}`, `stats`, `claim`, `put`, `clear`.
- `sw-client.mjs`: `initServiceWorker()` (not awaited by main), `cleanupServiceWorker()` (unregisters and drops caches when the `serviceWorker` setting is off), `clearDeviceCache() → {freedBytes}`, `swStatus() = {supported, registered, scope, controlling, cachedBytes, cachedFiles, reason?, script, version, outdated, persisted}`, `cachedOptimizedUrls()`, `readCached(url)`, `sendSwConfig()`. The SW message listener is attached at module import (before the first scene draws), so an early `p2p-get` gets an immediate "no" instead of a timeout. A running SW of another version sets `outdated`; for the Data-root copy the GM is warned once to copy it again. Persistent storage is requested on Chromium only (Firefox would prompt).
- `swarm.mjs`: `initSwarm()`, `swarmStatus() = {enabled, reason?, peers: [{userId, name, state, rttMs, upBytes, downBytes, bytesPerSec}], up, down, servedFiles, fetchedFiles, failures, lastFailure?: {userId, name, reason, local, remote, at}, banned, tracker?}`, `fetchFromPeers(url, {signal, onProgress, urgent})`, `holderCount(path, excludeId)`, `noteCached`, `noteEvicted`.
  - **Local origins stay out.** A client that reaches the server through a local origin (localhost, LAN; usually the GM on the host) neither seeds nor fetches (`reason: "local"`): its upload would share the server's link. The tracker still runs on the coordinator. For tests with several players on one machine, `localStorage["optimal-foundry.debug.allowLocalP2P"] = "1"` overrides this per origin.
  - **Tracker** (coordinator, memory only): clients announce every optimized path they cache (`MSG.P2P_HAVE {add, drop, reset?}`); the library, `sha256` and `p2pMinFileKB` are checked only at `MSG.P2P_WANT` time, which returns holders ranked by the requester's own measured throughput, else everyone's mean. Self-reported rates for oneself are ignored and rates are clamped to 100 MB/s. The coordinator sends `MSG.P2P_RESYNC` (clients re-announce with jitter) when it starts, when it takes over, and when a user (re)connects. A seeder asked for a file it no longer has drops it from the tracker.
  - **Transport**: native `RTCPeerConnection` with one negotiated DataChannel, ICE servers from `iceServers`, signaling over `MSG.P2P_SIGNAL` (perfect negotiation, per-session ids). ICE timeout 10 s; candidate types are recorded and the last failure is exposed.
  - **Source selection.** Urgent loads (canvas loading or counted urgent loads) use only peers already connected, and nothing behind a CDN profile; they warm links for later. Background loads may wait for ICE, with progress pings to the SW meanwhile. At most 2 files download at once per page; further misses go to the network.
  - **Transfer.** 1 MiB pieces, up to 3 peers with 2 lanes each, chunks ≤ min(`sctp.maxMessageSize`, 64 KiB), backpressure. A peer answering `busy` (at its upload cap) is dropped for that file at once on an urgent load; a preload lane backs off (400 ms × attempt, 6 attempts, signalling progress to the SW) and asks again. When the peers run out with part of the file delivered, the missing span comes from the host in one Range request instead of the whole file again. Endgame: an idle lane duplicates the oldest piece in flight from a single peer for over 2 s; the first copy wins. The whole file is checked against the library SHA-256; on a mismatch only a lone contributor is struck (3 strikes = banned for the session). A peer that keeps failing is cooled down for 60 s.
  - **Seeding** from Cache Storage, token bucket at `p2pUploadCapMBps`, at most 3 uploads and 2 per peer, never while the local canvas is loading. `p2pParticipate: false` → neither seed nor fetch.

## UI (`scripts/ui/`, `templates/`, `styles/`)

- UI text: titles, labels, icons and colors carry the state; explanations live in tooltips behind a `.of-hint` question mark (field hints in the Settings window, section intros in the dashboard, the welcome screen's descriptions) instead of paragraphs.
- `common.mjs`: formatting/i18n helpers and `LiveApplication`, an ApplicationV2 base that refreshes every 2 s but skips the refresh while a pointer button is held inside the window or a text field/select has focus, and keeps the DOM node of a part whose HTML did not change (tooltips and focus survive).
- `dashboard.mjs`: `registerUI()` at init (GM settings menu, Scene Directory context entries "Marcar como próxima cena"/"Desmarcar" with an indicator, and the player panel) and `OptimalFoundryDashboard` (GM only). Tabs: **Mídia** (in review mode first the "waiting for your approval" list from `reviewList()` with up to 3 document links per file, an ImagePopout preview for images and videos, checkboxes kept across refreshes, and approve selected / approve all (confirmed) / decline selected; a note for the current mode and one while the welcome screen is pending; stats, the last scan's "what the world uses" table by origin × outcome with unread external/SVG/pack counts, backfill state and controls, `lastError` as "file: reason" with the raw error in a tooltip, per-row Undo / Retry / Optimize again, bulk retry of the filtered list with confirmation, links to the documents that reference a missing file), **Rede** (effective profile and limits, CDN status with who measured it, per-player table with readiness for tiers 0–1, join-queue chip, stale rows), **P2P** (SW version/outdated/persisted, swarm, last failure, peers), **Pré-carregamento** (the automatic plan by tier with the reason for each scene or group, refreshed on `optimal-foundry.preloadPlanChanged` unless the GM is typing; marked next scenes; include/exclude editors), **Limpeza** (analysis on demand, checkboxes kept in the window across refreshes, empty selected/all after a confirmation that says it cannot be undone, progress while it runs, and the last result with kept files and reasons).
- `settings-app.mjs`: `OptimalFoundrySettings`, the GM-only Settings window (menu registered first, `restricted: true`). Foundry's own settings page lists no Optimal Foundry setting: GMs get the Settings, Dashboard and My connection buttons, players only My connection. The window shows preset cards (`PRESETS`: recommended, saver, quality, networkOnly; a card only fills the form, Save writes), the eight basic switches (`backfillMode` is a select), and an "Advanced" `<details>` grouped by files / network / sharing. It greys out the custom-profile keys unless the profile is custom, the resize limits while dimensions are kept, and the media switches while media is off; Save writes only changed keys and asks for a world reload when a `RELOAD_KEYS` setting changed.
- `tracker.mjs`: `OptimalFoundryTracker`, a frameless positioned `LiveApplication` (`window.frame: false`, classes `themed theme-dark`, `position: fixed` above `--z-index-ui`) for GMs only. Dragged by its head (`[data-of-drag]`, buttons excluded) with `setPosition`; the position is written to the client setting `trackerPosition` when a drag ends and read back in `_initializeApplicationOptions`. `trackerCollapsed` shows one compact line: the media icon with a short value (conversion progress, files waiting for review, queued count, `!` before the welcome screen), one colored dot per connected player (ready, loading, joining/waiting, unknown as a ring, stale faded; tooltip with name and state) and open P2P peers, plus the expand button; expanded it shows the media line (current conversion with progress, review count with a link, waiting for welcome with a link, paused, waiting for the network, off, all done), one row per connected non-GM client from `networkStatus().clients` with `upcomingReadiness()` (tiers 0–1) as a bar, state (stale, joining at position 0, queued at position > 0, loading, ready, waiting, unknown when the coordinator has no readiness for that user while tiers 0–1 are not empty) and a tooltip, plus the plan's tier counts and P2P totals as icons. A non-coordinating GM session says players show up in the coordinating session. `registerTracker()` adds a toggle tool `ofTracker` to the Tokens scene controls (GM only) and opens the panel at ready when `trackerVisible`; `setTrackerVisible(bool)` writes the setting, opens or closes it and re-renders the controls.
- `welcome.mjs`: `OptimalFoundryWelcome` (GM only, `standard-form`, shares the Settings layout) opens at ready while `welcomeDone` is false and closes on other GMs when one finishes. It offers the presets as four compact radio cards in one row with their description in a tooltip (preselects the matching one; when none matches, nothing is preselected and a "Custom" chip says the current quality values are kept unless a preset is picked), `backfillMode` (review, auto, off), `optimizeUploads`, `preloadEnabled`, `p2pEnabled`, `hostUploadMbps` and the tracker. "Network only" disables the media part. Submit writes the preset plus those values (changed keys only), then `welcomeDone`, then the tracker, and asks for a reload when a `RELOAD_KEYS` setting changed. "Not now" only closes it. `openWelcome()` reuses an open instance; the Settings window has a "Welcome" button that closes itself and opens it.
- `connection.mjs`: `ConnectionPanel` ("Minha conexão"), open to every user from the module settings and from a wifi button in the player list's latency/FPS row. It shows this device's cache (used of quota), P2P (peers, up/down), preloading, CDN and the Service Worker, edits the four client settings (`p2pParticipate`, `preloadOnThisDevice`, `cacheQuotaMB`, `p2pUploadCapMBps`) and has "Limpar cache deste aparelho" (`clearDeviceCache()`, with confirmation).
- `lang/pt-BR.json`, `lang/en.json`: keys `OPTIMALFOUNDRY.Settings.<key>.Name|Hint|Choices.<value>` for every setting plus UI strings. Both files carry the same key set.

## Cross-cutting rules

- No build step. Plain ESM `.mjs`, relative imports. Use `foundry.*` namespaced v14 APIs; no compatibility branches for older generations and no fallbacks for missing libWrapper.
- Never block the UI thread for long: chunk loops, `await` between items.
- Every subsystem fails closed (disables itself with a console warning) instead of breaking the game.
- Static Foundry files (`/scripts`, `/css`, `/lang`, module and system code) are not cached by the SW; owners with Cloudflare can add an edge cache rule for them (README).
