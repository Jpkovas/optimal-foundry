# Optimal Foundry: architecture and contracts

One client-side Foundry module (v14 minimum, verified 14.370). No server code: everything runs in the browser. One session of the active GM coordinates (`isCoordinator()`, see Core contracts). Module id `optimal-foundry`. Requires `lib-wrapper` (no fallback without it).

The Foundry source this targets ships inside the Foundry application, under `resources/app` (`client/` unminified ESM, `common/`, `dist/` minified server). Read it instead of guessing APIs.

## Core contracts

- **Setting changes.** Every setting's `onChange` fires `optimal-foundry.settingChanged(key, value, options, userId)` (bare key, e.g. `"library"`). Listen to that, never `updateSetting`/`clientSettingChanged`: the first write of a world setting is a Setting *create*, which `updateSetting` misses, and client settings never fire it. The three profile-controlled settings (`maxConcurrentRequests`, `preloadSharePct`, `staggerJoin`) are greyed out in the settings form unless the profile is "custom". `effectiveNetwork().p2p` is `p2pEnabled` on every profile except `cdn`: behind a caching CDN players never exchange files (the edge already spares the host, so P2P would only spend the players' upload and exchange their IP addresses). `preloadBytesPerSec` is the ceiling of the preload budget on every profile.
- **Socket.** Envelope `{t, p, from, to?, rid?, re?, err?}` on `module.optimal-foundry`; the server-supplied sender id overrides `from`. A broadcast is emitted with no options argument at all: socket.io turns a trailing `undefined` into `null`, and the server's `{recipients} = {}` destructuring throws on `null`, which silently drops the message. A handler's return value answers a `request`; `undefined` sends no answer (passive sessions use this so they never race the coordinator). Request ids carry the session id, and a reply is accepted only from the user the request went to (`senderId === to`); a forged reply leaves the real one pending.
- **Coordinator session lock.** `game.users.activeGM` picks the user; a user may have several sessions (desktop app plus a browser tab), and messages addressed to the user reach all of them. Each GM session sends `MSG.COORD_BEAT {sid, startedAt}` to its own user at ready and every 10 s, and answers a new session's first beat at once. A closing session sends `{sid, bye: true}` on `pagehide`, as a plain broadcast (a world that is shutting down has no user list left for a targeted emit; every other user ignores it); a crashed one expires after 75 s (longer than Chrome's 1-minute timer alignment for hidden tabs, so a backgrounded coordinator is never taken for dead). `isCoordinator()` is true only on the active GM's oldest live session (by `startedAt`, then `sid`). `optimal-foundry.coordinatorChanged(bool)` fires when that changes (beats, expiry, any GM `userConnected`). Right after `ready` a new GM tab counts as coordinator until the older tab's answer arrives (one round trip); everything that acts on it is debounced or delayed past that.
- **Batched library writes.** The library is one world setting, so each write sends the whole object to every client. Every write of a client runs on one promise chain that re-reads the library inside the chain. `putEntries(entries, {now})` queues partial entries (merged field by field) and writes 20 s after the last call, at most 60 s after the first queued entry; `{now: true}` writes at once and its promise settles with that write. Await it only when the entry must be durable (a `done` entry right before references are re-pointed); otherwise `.catch` it. `removeEntries` drops queued writes for those keys, then writes on the same chain. `flushLibrary()` writes the queue now and resolves when every write has settled (never rejects; used on pause, loop end, undo and `beforeunload`). `getLibrary()`/`getEntry()` return the merged view: stored value, then pending writes, then the queue. `findByOptimized` indexes only `done` entries; `optimal-foundry.libraryChanged` fires after each re-index (on `settingChanged("library")`).
- **Units on screen.** Sizes are binary and labelled KB/MB/GB (1 MB = 1,048,576 bytes, the unit of every size setting); rates are megabits per second (1 Mbps = 125,000 bytes/s, the unit of `hostUploadMbps` and `p2pUploadCapMbps`). The UI formats both through `formatBytes`/`formatMbps` in `ui/format.mjs`; internal fields stay in bytes and bytes per second.
- **A player chooses before sharing.** `connectionChoiceDone` (client) is false until the player answered the first-run card on that browser. Until then a non-GM browser opens no peer connection, answers no signaling and announces nothing (`swarm.mjs` `blocker()` returns `"notChosen"`).

## Product rules (from the owner)

1. Every upload is optimized before it reaches the server; only the optimized file is stored. If the uploading client cannot encode (no WebCodecs / WebP canvas encoder), the original is uploaded and the GM converts it in the background (`MSG.CONVERT_REQUEST`).
2. Existing world assets are optimized in the background by the coordinating GM session, the way the GM chose: automatically, only what they approved (review first, the default), or not at all. Nothing converts existing files before a GM finishes the welcome screen. The backfill never deletes or overwrites originals; documents are re-pointed to the optimized copy, and every rewrite is undoable from the library until the GM empties the original in the Cleanup tab (see `cleanup.mjs`). Heavy conversions (every video, audio above 20 MB, images above 30 MB) wait until no player is connected, unless the GM asks for them now.
3. **Keep resolution by default** (`keepResolution: true`): only codec/bitrate/quality change. Resizing happens only when the GM turns it off (`maxImageSide`, `maxVideoHeight`). WebP cannot exceed 16383 px per side: such images are skipped (`tooLarge`) when keeping resolution. `tooLarge` also covers an image above the pixel budget (100 megapixels of source, halved when `navigator.deviceMemory` is 4 GB or less; decided from the file's header, before decoding) and an output predicted to exceed `maxOutputBytes` (decided before encoding).
4. Players use Chrome/Edge/Firefox only. VP9 alpha and Ogg Opus are fine.
5. Everything is configurable. Nothing owner-specific is hardcoded; the module is shared with friends who may have no domain, no CDN and no Service-Worker header (they copy the bridge file once; the UI tells them how).
6. UI text in Brazilian Portuguese (plain, direct) with English fallback.
7. Preloading is automatic: the GM never has to mark scenes (marking only puts a scene first). The GM can keep a small floating tracker of the module's state over the canvas; players never see it.

## Formats and naming

- Image → WebP (`OffscreenCanvas.convertToBlob({type:"image/webp", quality})`), verified by `blob.type`. Lossless sources (PNG, static GIF, BMP, TIFF) are also encoded lossless (quality 1) and the lossless file wins unless it is more than 15% larger than the lossy one: flat map art grows 2-3× as lossy WebP but shrinks 80-90% lossless. SVG never touched. Already WebP/AVIF → skip.
- Static GIF → WebP. Animated GIF: on upload kept as-is. In backfill, converted to WebM VP9 with alpha only if every reference is a texture/video-capable field and `convertAnimatedGif` is on; otherwise `animatedGifImageField`.
- Video → WebM VP9 via Mediabunny `Conversion`. Target bitrate (`videoBitrate`): bits per pixel from `videoQuality` anchored at 1080p30, scaled by (pixels/1080p)^0.75 × (fps/30)^0.5, capped at 70% of the source's video bitrate (a leaner target would only inflate the file), clamped to 0.5–20 Mbps (64 kbps floor for animated GIF/APNG). Audio track → Opus unless `videoStripAudio`. Audio → Ogg Opus. Ogg/Opus input and MP3 below `skipMp3BelowKbps` are skipped. Every Ogg Opus output is end-trimmed (`trimOggOpus`) so it decodes to the source's exact length. A looped sound (`loop: true`: an ambient sound, a playlist track set to repeat; up to 600 s, longer ones stream and never loop gaplessly) is skipped as `loopLength` unless the output decodes to the source's length within 1 ms, which an MP3 source, padded by its format, does not.
- The kind comes from the references when known (`optimizeUrl(path, {kind})`, e.g. an audio-only `.webm`), else from the extension.
- Kept original when the output is not at least `minSavingsPct` smaller (`noSavings`).
- Output name `<sanitized-stem>.of-<first 8 hex of SHA-256(output)>.<ext>`. Content-hashed names are never reused for different bytes, which is what makes the year-long CDN cache safe.
- Output location: same folder as the original; originals under `modules/`, `systems/`, Foundry's core public folders or on another host go to `worlds/<this world>/optimal-foundry/<original dir>/` (`naming.outputLocation` / `ensureDirectory`): inside the world folder, so a backup or a copy of the world carries its optimized copies.

## Media (`scripts/media/`)

- `converter.mjs` (page side), `converter-worker.mjs`, `converter-bytes.mjs`: `canConvert(kind)` (memoized probe); `conversionBlocker() → null | "insecure" | "unsupported"` (synchronous: why this browser cannot convert anything; "unsupported" also covers a worker that could not start, known only after the first probe); `optimizeFile(file, {name?, kind?, referenceKinds?, signal?, onProgress?, loop?, maxOutputBytes?})`; `optimizeUrl(path, sameOptions)` (no-store fetch, ranged reads for video/audio). `OptimizeResult = {status: "done"|"skipped"|"failed", kind, file?, sha256?, bytes?, originalBytes, reason?}`. The conversion runs in a module worker (one warm worker; a concurrent call gets a temporary one; an abort or a worker error terminates it), so a large map never blocks the canvas, and there is no in-page path. The page keeps what needs it: settings, routes, naming the output and the loop check (`decodeAudioData` does not exist in workers). `converter-bytes.mjs` holds `imageDimensions` (the pixel budget, read from the header) and `trimOggOpus`.
- `upload-hook.mjs`: libWrapper `WRAPPER` on the static `FilePicker.upload`, re-entry guarded by a WeakSet; `skipUploadHook(file)` adds a module-internal file (the cleanup's empty files) to it. Converts when `optimizeUploads` and capable, uploads the optimized file, then registers it (coordinator → `putEntries`, anyone else → `MSG.REGISTER_OPTIMIZED`). Such entries are keyed by the stored optimized path itself (`original === optimized`, `uploadedName`). A conversion shows a progress notice after 1.5 s; clicking it, or 90 s without progress, uploads the original instead. Success toasts of a multi-file drop merge into one. Optimized files above 95 MB warn about Cloudflare's 100 MB upload limit only when `tunnelLimited()` (the CDN probe saw Cloudflare, `behindCloudflare()`, and this page is not on a local origin); the backfill passes `maxOutputBytes` in the same case. A browser that cannot convert because the page is not a secure context says so (`Media.NotCapableInsecure`) instead of blaming the browser.
- `references.mjs`: `installRewriteGuards()` (every client, at init) keeps core's PlaylistSound#_onUpdate from throwing "audio not unlocked" when a rewrite changes a track's `path` on a client that has not unlocked audio yet (the Sound is created lazily once it unlocks). `collectReferences({includeCompendia, signal, unread}) → Map<path, Ref[]>` (`unread = {external: Set, vector: Set}`, optional, collects media on other hosts and SVG that are dropped) walks every world document by schema (`FilePathField` kinds from categories, `HTMLField` img/video/audio/source/a, Markdown `![](…)`/`[](…)` targets, `TypeDataField` system models, plain `system`/`flags` strings with media extensions). Scene levels hold background/foreground/fog (`Scene#background` is a shim, never written). `collectDocumentReferences(doc, {children})` does the same for one document. `rewriteReferences(map, {refs, protect}) → {updated, skipped, failed, deferred, failedFrom}` gives each document all its changed fields in one update and sends the documents in groups (one request per document type under the same parent, and one per top-level type in the world or in a compendium, cut at 200 documents or about 1 MB of changed data), reads every value back from the stored source, which alone decides success, and returns protected refs untouched in `deferred`. Adventures are never scanned or re-pointed (the documents they create on import are). `pacer(signal)` yields to the browser by elapsed time in long walks. **Wildcard token art:** an Actor whose prototype token has `randomImg` and a `*` in `texture.src` yields a pattern reference (`ref.pattern` = the pattern) listed under the pattern itself as key (`isPatternKey`: real keys never hold `*`); `matchPattern(pattern)` lists the media files via `FilePicker.browse("data", pattern, {wildcard: true})` (null when the server cannot answer) and `expandPatterns(refs)` moves the pattern references onto those files, so they are collected like any other file. `rewriteReferences` ignores pattern references; `setTokenPatterns([{uuid, from, to?}])` changes the field in one update with the rewrite flag, keeping `from` in `flags.optimal-foundry.tokenPattern`, or (no `to`) restores it from the flag and removes the flag.
- `cleanup.mjs`: `findCleanupCandidates({signal}) → {candidates, inUse, outsideWorld, brokenCopy, gone, missing}` (`missing`: originals not on the server right now; nothing is recorded for them), `emptyOriginals(items, {signal, onProgress}) → {emptied, kept: [{original, reason}], freedBytes}`; both coordinator only. Foundry's server cannot delete (manageFiles only browses, creates directories and configures paths), but `Files.upload` sets `overwrite` when `UPLOADABLE_FILE_EXTENSIONS[ext]` is in `MEDIA_MIME_TYPES` and never inspects content, and express-fileupload keeps a named 0-byte part. So the cleanup empties an original by uploading `new File([], <same name>)` into its folder through `FilePicker.upload` (marked with `skipUploadHook()` so the upload hook does not convert it). Eligible: a `done` entry converted by the module's own optimizer (it carries the `source` fingerprint read from the original), not `cleaned`, original ≠ optimized, whose raw key (never re-normalized: that would cut a decoded `#`) is under `worlds/<this world>/`, has no `#`, `?`, empty, `.` or `..` segment, and an overwritable extension. "Used" is a text search, not the reference walker, over everything the world loads: the manifests of the world, its system and its active modules (a world's background and description live only there), every world document (chat, macros and settings included, but not the module's own library), and every document of every compendium, the system's and the modules' too, as written, encoded and lowercase. Any mention keeps the file, and so does a file pattern that matches it (wildcard token art names no file). Whatever cannot be read or decided keeps the file: a compendium that cannot be read refuses the whole cleanup with a message naming the pack. The text read is kept per part for 10 minutes (an analysis is usually followed by a run) and read again only where a document hook fired. Not detected: other worlds on the server (the confirmation dialog says so in plain words, next to "this cannot be undone"), packs of disabled modules, and macros that build a path at run time. Analysis also needs HEAD 200 with content and the optimized copy's HEAD size equal to `bytes`; an original at 0 bytes is marked `cleaned`, one at 404 is counted as `missing` and never marked (a renamed folder or an unmounted drive comes back). `emptyOriginals` holds backfill's `beginCleanup()`/`endCleanup()` section (undo refuses to start while it is held, and the cleanup refuses while an undo runs) and works in groups of 10: check that this session still coordinates (else the rest is kept as `notCoordinator`); search the documents again; check each item (eligible, unmentioned, HEAD with Content-Length > 0, `fingerprintOf` equal to `source` or else size equal to `originalBytes`, optimized copy downloaded and matched against `bytes` and `sha256`); write `cleaned` for the checked items in one durable write BEFORE any upload (a failed write empties nothing); upload; then HEAD each original: 0 bytes means emptied, the old fingerprint means `uploadFailed` and anything else means `changed` (both get the mark cleared again), and an unreadable file stays marked as `uncertain`. Emptied entries keep `status: "done"`, so `processItem` re-points any later reference to the optimized copy (it treats `cleaned`, or an original HEAD at 0 bytes, as final), and `undo()` keeps `cleaned` entries and originals at 0 bytes.
- `backfill.mjs`: `initBackfill()`, `scan()`, `start()`, `pause()`, `isRunning()`, `backfillStatus()` (also `review` count, `waitingForPlayers`, `mode`, `waitingWelcome`), `runHeavyNow()`, `reviewList()`, `approve(originals?)`, `decline(originals)`, `undo(originals?)`, `retry(originals)`, `fingerprintOf(headers)` (the `source` fingerprint: ETag, else Last-Modified|length). Coordinator only, one conversion at a time. **Pattern rewrite:** after each re-pointing batch, `rewritePatterns` moves an actor's pattern to the copies (`goblin-*.png` to `goblin-*.webp`) only when every file the pattern matches has a stored `done` entry, an unreplaced original and an intact copy in its own folder, all with one extension, and the new pattern lists exactly those copies (no brace/bracket syntax, literal extension); otherwise a later scan retries. Undo and self-repair put the old pattern back from the flag (`restorePatterns`), once per actor, except when a file of it stays optimized (emptied or gone original). A copy missing from disk drops out of the new pattern's listing, so only a listed but cut-short copy is seen by the repair. `reviewList()` keeps a review item whose converted original was replaced (`replacedBy` fingerprint) until an entry records that file.
  - **Gating.** Before each item it waits (up to 120 s) while this canvas is loading or `playersBusy()` (a remote player joining, drawing a scene or loading urgently), then for an idle callback. `scan`/`start` refuse when `mediaEnabled` is off, and `start` when `backfillMode` is "off" or before `welcomeDone`. `start` scans when the queue is empty or no scan ran this session yet (a document edited before the first scan queues one item). `kick()` restarts the loop when work arrived while it was finishing, and a loop that stops because another session took over clears `state.active`, so the auto-start runs again when the role comes back. Start/Pause in the dashboard also write `backfillPaused`, so a pause survives a reload. Auto-start (30 s after ready, 5 s after the welcome screen or a mode change) and starts from new references need `autoAllowed()`: media on, mode not "off", not paused (persisted or this session), and `welcomeDone`. When only the pause blocks it, the timer still runs one scan (review list and scan table; nothing converts). `backfillStatus().paused` includes the persisted `backfillPaused`.
  - **Heavy work waits for the players.** Every video, and audio or images whose original is above `HEAVY_AUDIO_BYTES` (20 MB) / `HEAVY_IMAGE_BYTES` (30 MB), is held in `state.heavy` while any non-GM user is connected (`backfillStatus().waitingForPlayers`); a player arriving in the middle of one stops it. It goes back in line when the last player leaves, or at once with `runHeavyNow()` (the dashboard's and the tracker's "Convert now"; like an approval it also resumes a paused optimization).
  - **Self-repair.** A scan checks that the optimized copies the documents use are still on the server, whole (a manual scan every time, the optimizer's own scans once per session). References to a copy that is gone go back to the original when it still has content, the entry is forgotten so the file converts again, and the count goes to `scanReport.repaired`.
  - **Failures that are not the file's.** A conversion that reports no progress for a long time is stopped (its worker is terminated) and counts as a failed attempt; several uploads failing in a row stop the run (`Library.UploadStopped`), because then the server is the problem.
  - **Modes** (`backfillMode`: auto | review | off, default review). `scan()` classifies as before, then `splitForReview`: "auto" queues everything; "review" keeps conversions whose original is not in `reviewApproved` in `state.review` (rewrites of converted files still run); "off" queues nothing (no rewrites either). New references found by the document hooks follow the same rule. `reviewList()` → `[{original, kind, refs: uuid[]}]`; `approve(originals?)` (all when omitted) writes `reviewApproved` before anything converts, moves the items to the queue, clears `backfillPaused` and starts (or kicks a running worker; before the welcome screen the approval is only saved); `decline(originals)` writes `{status: "skipped", reason: "declined"}` (durable) only over no entry or a failed one, so no scan offers them again until Retry forgets the entry. Every `reviewApproved` write goes through one promise chain that recomputes the list from the last write (an approval and a prune never overwrite each other); each scan prunes approvals whose original has a final entry (done, skipped, failed ×3). A mode change stops the worker (a player's request finishes), waits for a scan already running, rescans and auto-starts if allowed. Right before working on a non-urgent item, `held()` checks the mode and approvals again: "off" drops it, an unapproved conversion in review mode goes back to `state.review` (so a stale queue never converts without approval). A converted original whose source changed on disk is a new conversion and needs approval again in review mode. `reviewList()` drops items that got a final entry meanwhile (a player's request). A request for a path documents already use honours the mode and the pause; `REGISTER_OPTIMIZED` is accepted only with `original === optimized` and no existing entry. Retry in "off" does not re-optimize restored entries (nothing would re-point them); after a retry an idle, allowed worker starts. `library.mjs` `willConvert(path)` (true in auto, in review only for approved originals, false when off, paused, before the welcome screen or with media off) tells the preload whether to leave an unconverted original out of the queue; `isApproved`/`forgetApproved` keep a cached Set of `reviewApproved`.
  - **Queue.** Candidates are referenced media that are not optimized, not already-optimal formats, and not `skipped` or `failed` ×3. Order: rewrites first, earlier failures last, then `preloadRank()` (the preload queue: what players are viewing, the active scene's neighbours, …), then kind, reference count, name. It re-sorts 2 s after a `nextScenes` or active-scene change. Documents created or edited mid-session (imports, drags) are scanned by hooks (debounced per uuid): references to converted files are re-pointed at once, new media is queued.
  - **Item.** HEAD the original (its ETag, or Last-Modified|length, is the `source` fingerprint; 404 → `skipped/missing` with up to 10 referencing uuids in `refs`). A `done` entry whose source changed is converted again. Convert → upload → `putEntries(done, {now})` awaited → re-point. Re-pointing is batched (20 originals, or when the loop ends) into one `rewriteReferences` call, and is refused (`notPersisted`) unless the persisted `done` entry carries that optimized path. `protectActiveScene` defers refs in scenes someone is viewing and in playing sounds; they retry on `canvasReady`, sound stop, scene change and every 60 s. Player requests and new references run as urgent items, even while paused.
  - **Crash marker.** `localStorage["optimal-foundry.backfillCurrent"]` (world id + path) is set before each conversion and cleared after it and on `pagehide`. A marker found at the next scan records `failed/interrupted` with attempts+1, so a file that crashes the renderer is retried at most 3 times.
  - **Undo / retry.** `undo` waits for the loop, flushes the library, re-points optimized → original, and marks those entries `{status: "skipped", reason: "restored"}` in one write, keeping `optimized`; nothing converts them again until `retry`. Entries whose original is missing, `cleaned` or at 0 bytes are kept, and undo refuses to start while the cleanup runs. It restarts the backfill if it was running. `retry(originals)` makes restored entries `done` again (re-pointed at once, no encode) and forgets skipped/failed ones so the next scan converts them; it returns the number of entries affected.
  - `backfillStatus() = {running, paused, phase: "idle"|"scanning"|"converting"|"rewriting", current?: {original, kind, progress, urgent}, queued, run: {done, skipped, failed}, deferred, waitingForPlayers, review, mode, waitingWelcome, lastError?: {path?, reason, detail?}}`. `scan()` resolves `{paths, convert, rewrite, review, kinds: {image, audio, video}}` or `null`; world compendia are read from the server at the first scan of a session and at every manual one, and kept in between (the document hooks say which documents to walk again). Each scan also stores the `scanReport` world setting: `{at, total, byOrigin: {world|module|system|core|data|otherWorld: {optimized, light, queued, skipped, failed}}, external, externalExamples, vector, unreadPacks, unreadPackDocuments, includeCompendia, repaired}` (`ORIGINS`, `OUTCOMES` exported). Origin comes from the path (mirrored `worlds/<world>/optimal-foundry/<path>` copies count where their original lives); `light` is a webp/avif/ogg/opus file, which is never queued or recorded. `external` (another host or protocol-relative) and `vector` (SVG) are what `collectReferences({unread})` saw but `mediaKey` drops; `unreadPacks` counts module and system packs (and world packs when `includeCompendia` is off), which are never read because a module update would put their documents back. The dashboard's Media tab renders it as a table per origin with notes.

## Network (`scripts/net/`)

- `scheduler.mjs`: `initScheduler()` at `init`; `networkStatus()`; `schedule(fn, {priority: "urgent"|"preload", url?, signal?})` (`fn({signal, progress})`); `waitForPreloadWindow`, `registerStatusProvider`, `onClientGone`, `askCoordinator`, `tellCoordinator`, `serveCoordinator`, `sceneReady`, `playersBusy()`, `chargeBatch(items, from)`, `settleBatch(results, from)`, `clientOrigin(userId)`, `loadInBackground(srcs)`, `LATER_TIER`.
  - libWrapper on `TextureLoader.prototype.loadTexture`, `TextureLoader.prototype.load` (caps `maxConcurrent` per client behind a tunnel) and `Sound.prototype._load` count urgent loads. Same-origin textures that fail are retried up to twice after a no-store HEAD probe (a real 4xx gives up). PIXI loads textures on the main thread (`preferWorkers: false`), so they go through the SW and Resource Timing.
  - Idle = no urgent load, canvas not loading, and no foreign resource entry for `idleSeconds`. A video texture, a streamed sound or a media element that is downloading without enough to keep playing counts as busy too (Resource Timing only lists a request when it ends). Every 2 s each client sends `MSG.CLIENT_STATUS {inflight, urgent, bytesPerSec, sceneReady, idle, cacheBytes, joining, local, publicOrigin, secure, cache, p2p, rttMs, preload}` as a request the coordinator answers: `local` is true only on the server's own machine (`isLoopbackOrigin`; a private address may be a VPN across the host's uplink, so it is charged like any remote client), `secure`/`cache`/`p2p` say whether the page is a secure context, a Service Worker controls it and the browser can share right now, and `rttMs` is the round trip of the previous report. When this browser's urgent count goes from 0 to 1 it fires `Hooks.callAll("optimal-foundry.urgentLoad")` and reports at once. A client that says it is busy for 75 s without a break is no longer believed.
  - **Adaptive budget.** The bucket's ceiling is `preloadBytesPerSec` (the share of `hostUploadMbps`, which is often wrong or eaten by a screen share), and the rate adapts below it: one step per 5 s: when more than half of the clients that are not on the server's own machine see even their best recent round trip above twice their own best of the session plus 100 ms, the host's uplink is queueing, so the rate is halved (never below 1/8 of the ceiling); otherwise it climbs back by a tenth of the ceiling. The last tier ("later") gets at most half of the rate, and a client refused for tokens on a tier holds a 5 s claim that keeps later tiers of other clients away from the bucket. Settlement uses the coordinator's own record of what it charged, never a client's.
  - Staggered join: the joiner's turn handshake starts at `setup` (before `ready`) with a raw listener for `JOIN_TURN`, accepted only from the active GM. The coordinator records arrival order on `userConnected` but gives the turn only to joiners that have announced themselves (`joining: true`), one at a time, until `sceneReady` or 20 s. Queue position is shown to the joiner and in the dashboard.
  - `networkStatus() = {profile, cdn, inflight, urgent, preloading, textureRetries, bytesPerSec, idle, sceneReady, joinTurn, enabled, clients?, budget?}`; coordinator only: `clients` `{[userId]: {name, inflight, urgent, bytesPerSec, sceneReady, idle, joining, local, secure, cache, p2p, cacheBytes, preload: {done, total}, stale, queuePosition?}}` and `budget` `{rateBytesPerSec, ceilingBytesPerSec, slowed, rttMs}` (the rate in force, the ceiling from the settings, whether round trips pushed the rate below it, the median recent round trip of the remote clients).
- `preload.mjs`: `initPreload()` at ready, `preloadStatus()`, `markNextScene(sceneId, bool)`, `preloadPlan()`, `upcomingReadiness()`, `preloadRank()`, `buildQueue(maxBytes)` (pure over `game`, used by the tests).
  - **Queue (coordinator), automatic.** It always covers everything players may need, most likely first; the token bucket, P2P and the idle window set the pace, and a client above 80% of `cacheQuotaMB` skips tier 3. Tier 0 "now": scenes in `nextScenes` (exclude ignored), the GM's `canvas.scene` when not active, and the `viewedScene` of each connected non-GM user when not active. Tier 1 "probably next": the active scene's other levels (when more than one) and non-hidden AmbientSounds, its whole playlist, playlists with `playing`, the active scene's navigation-bar neighbours (`navigation` scenes by `navOrder`, 2 after and 1 before), scenes holding the destinations of its enabled `teleportToken` behaviors (absolute `Scene.<id>.Region.<id>` uuids only), its folder neighbours in the directory's order (folder `sorting` "a" = name, "m" = `sort`; root uses `game.scenes.sortingMode`), and `preloadInclude`. Tier 2 "this session": the other navigation-bar scenes by distance from the active one, the rest of the playlists linked to tier 0–1 scenes, and `img` + prototype token texture of actors any non-GM user owns. Tier 3 "later": every other scene by `_stats.modifiedTime` desc, the playlists linked to those, every other playlist, and `collectDocumentReferences()` of journals any non-GM user can observe. Each scene brings its visuals, its first track (`playlistSound`, else the playlist's first) and its non-hidden AmbientSounds at its own tier; the rest of its playlist one tier later. Hidden tokens, tiles and other placeables are included (core loads them too); only hidden AmbientSounds are left out. `preloadExclude` and `preloadMaxFileMB` apply. The build also records a plan (`{type: scene|playlist|actors|journals, id, name, tier, reason, files, bytes}`, entries with no new file dropped) that `preloadPlan()` returns with per-tier totals for the dashboard. Items are the paths the documents reference, with size and kind from the library, except that an original already converted but not yet rewritten resolves to its optimized copy, and an original the backfill has not processed yet (no library entry, convertible by name, and `willConvert(path)`: auto mode, or approved in review mode) is left out: warming it would spend the host's upload on a file that stops being used seconds later. The library change after conversion rebuilds the queue. A scene leaves `nextScenes` when it is activated. The queue rebuilds (debounced) on relevant changes, with per-document keys (`WATCHED`: scene content and `navigation`/`navOrder`, Region behaviors, Playlist `playing`, Actor `img`/`prototypeToken`/`ownership`, Journal pages and ownership, User `role`/`character`), on `userConnected`, on setting and coordinator changes, and on library changes at most every 15 s (a running backfill writes it every few seconds). `User#viewedScene` is a client property that fires no hook, so the coordinator compares the connected players' viewed scenes every 3 s. Journal media lists are cached per journal id and dropped by JournalEntry/JournalEntryPage hooks. The walks stop at `MAX_ITEMS` (5000); the per-user "have" sets hold 4× that, so a queue change at the cap does not evict files still queued. `preloadRank()` returns the build's rank: every path the queue walked, as the documents hold it (originals not converted yet included), by first position, which `sortQueue` in the backfill uses. `predecodeNext` decodes the predicted next scene on each client: the first marked scene, else the active scene's next navigation-bar neighbour, else its next folder neighbour.
  - **Batch protocol.** When its preload window is open (idle, join turn, scene drawn), a client asks `MSG.PRELOAD_NEXT {have?, full?}` (`have` only on the first ask, or when the GM answers `needHave` after a hand-over; `full` above 80% of `cacheQuotaMB` or with `preloadScope` "session", which skips tier 3). The coordinator answers up to 8 items already charged by `chargeBatch` (the adaptive bucket, burst 2 s; a file larger than the burst waits for a full bucket and arrives alone; a client on the server's own machine is never charged; nothing while a remote player joins, draws or loads urgently). Each item says who uploads it: `host` (costs its size), `peer` (a sharer holds it: free unless it comes from the host after all) or `edge` (the CDN holds it: free) plus `waitMs`, `total`, `done`. The client warms them through `schedule` (at most 3 at once, with the header `X-Optimal-Foundry-Preload: 1`, body drained; exported as `warm` for the tests), then sends one `MSG.PRELOAD_DONE {results: [{src, bytes, ok, aborted, reason}]}`, where `bytes` is what the host uploaded for the file as far as the page can tell (nothing when `X-Optimal-Foundry-Source` says the Service Worker answered from its cache or from a peer, or when the CDN's edge already held it); `settleBatch` settles that against what the GM charged, within bounds (a file the client was not handed is ignored, each file settles once, aborted items are refunded down to their partial bytes and offered again), adds only ok/tooLarge results to that user's `have`, and keeps 4xx files out for 10 min. The client sleeps `max(250, waitMs)` between batches; `MSG.PRELOAD_WAKE` (sent after every queue change) cuts an empty-queue sleep short. There are no per-file grants.
  - **Aborts.** Any urgent load aborts in-flight preloads, in the page and in the Service Worker (`abortSwPreloads`: the worker downloads on its own behalf, so aborting the page's fetch alone would leave that download running), except fetches past 50%.
  - **`have` sets** live for the session only: in memory on the coordinator (max 5000 per user), and on the client seeded from the SW's Cache Storage when the SW controls the page. Files not served through the SW are capped at 32 MB (larger ones would not stay in the HTTP cache) and reported as `tooLarge`.
  - **Who uploads each file.** Without a CDN, with sharing on, an eligible optimized file handed to one client that can share right now (`canSeed`) is reserved for it for up to 120 s; the other sharers take it from that client through the swarm. A browser that cannot share (no local cache, opted out or not chosen yet, plain HTTP) neither holds such a reservation nor waits on one. Behind a CDN the first handout of a file fills the edge from the host: one client gets it, charged, and once it reports the file the edge serves everyone else for free. A client whose remaining items are all reserved gets an empty batch with `waitMs` 2 s and asks again; a reservation ends on its TTL, when the fetcher leaves or can no longer share, when its fetch fails, and about 5 s after the fetcher reports the file, so nobody starves.
  - A GM on the server's own machine (loopback) does not warm anything (it would save nothing) but still serves the queue (`preloadStatus().running === false`). `preloadScope` (client setting) sets how much a browser preloads: "all", "session" (never the last tier) or "off"; `preloadStatus().enabled` is false when the world or this browser turned preloading off.
  - **Pre-decode** (`predecodeNext`, off by default): once every image of the predicted next scene (see above) is warmed, decode them into Foundry's texture cache in the background (`loadInBackground`, 2 at a time, no urgent accounting), only on performance mode MED or higher and below 70% of core's texture memory limit.
  - `preloadStatus() = {enabled, running, queueLength, current?, done, total, paused}`. `upcomingReadiness() = {[userId]: {have, total, bytesLeft}}` for the tier 0–1 items (coordinator only).
- `cdn.mjs`: `detectCdn({force})` (coordinator, at ready): HEAD (fallback 1-byte Range GET) a media file twice and read `cf-cache-status`; caching CDN when the header exists and is not `DYNAMIC`/`BYPASS`. Stores `{cdn, status, origin, url?, by?, checkedAt}` in `cdnStatus` (unchanged results rewritten at most hourly). A GM on a local origin cannot see the edge: it asks a player to probe (`net.cdnProbe`) on that player's first `CLIENT_STATUS` reporting a remote origin and a drawn scene (so its handler exists and it sees the edge; a fixed delay after `userConnected` timed out on slow joins and picked local-origin players), and keeps a remote result for 7 days; `force` (the dashboard button) asks again now and never stores "local". The stored result also carries `cloudflare` (the probe saw a `cf-cache-status` header at all, cached or not), which `behindCloudflare()` returns; the upload hook and the backfill use it for Cloudflare's 100 MB upload limit. The GM is told only when a CDN is found or lost (a quick tunnel changes hostname at every restart, which is not news). `isLoopbackOrigin(hostname?)` (the server's own machine: the only client that costs the host no upload), `isLocalOrigin(hostname?)` (cannot be behind a public CDN; for the probe only), `initCdnResponder()`.

## Service Worker and P2P (`scripts/p2p/`, `sw.js`)

- `sw.js` (self-contained classic script, `VERSION` must equal `SW_VERSION` in `sw-client.mjs`). Registered with scope `/` (route root): first an existing registration's script, then the bridge at the Data root, `/optimal-foundry-sw.js` (one line that loads this file with `importScripts`; no header needed), then `/modules/optimal-foundry/sw.js` itself (needs `Service-Worker-Allowed: /`). Under the bridge `self.location` is the bridge's URL, so every path here is built from `self.registration.scope`. A module cannot put the bridge at the Data root itself (`.js` is not uploadable): the GM copies it once, and module updates then reach the worker without a new copy.
  - Intercepts only same-origin GET requests for media extensions, whatever the folder is called; everything else passes through.
  - `.of-` paths (immutable): Cache Storage `optimal-foundry-v1` first. On a whole-body miss, ask the page that made the request `{type: "p2p-get", url, id}` over a MessageChannel, but only a page that sent `config {p2p: true}` to this worker instance; the page acknowledges at once (the SW gives it 1.5 s), then pings progress, then answers with a verified Blob or `null`; the SW gives up after `p2pTimeoutSec` without progress. Otherwise one network fetch (default cache mode, so the HTTP cache may answer) streams to the requester and stores the full 200 response. LRU eviction against `cacheQuotaMB` (metadata in IndexedDB, reconciled on the first config message); the page is told `cached`/`evicted` so the swarm announces it.
  - Range requests: a hit is sliced from the stored body (206). A miss goes straight to the network with the original Range header, never waits for P2P or a download in flight, and is not stored; audio/video element loads never wait for P2P either, so media streaming starts at once. Whole files reach the cache through preload.
  - Mutable media (any other media path; Foundry overwrites same-name files silently): stored in the same cache, and every hit is revalidated with the stored ETag/Last-Modified at most once per 30 s (304 serves the copy, 200 replaces it, 404/410 drops it, network error or 5xx serves the copy). Never fetched over P2P. The config field `revalidateMutable` (default true) turns it off and drops those copies.
  - Preloads: a request with the header `X-Optimal-Foundry-Preload: 1` is background warming. The header never reaches the server, the download runs with `priority: "low"`, and the page can stop it with `abort-preload`, which discards the partial copy; a download the game itself started waiting for is no longer a preload and cannot be aborted.
  - Every response built by the worker carries `X-Optimal-Foundry-Source`: `cache` (a stored copy, or a download another request had already started), `p2p` (from other players) or `net` (downloaded from the server for this request), so the page can tell what a file cost the host. On a `net` answer the download's `cf-cache-status` is passed to the page as well (never stored with the copy), so the budget can tell an edge hit from a fill.
  - Switching itself off: once the module is disabled or uninstalled no page code is left to remove the worker, so it counts game-page loads in IndexedDB and every `config` message (the page's hello, repeated with each stats refresh) resets the count. A load that finds 3 loads without one unregisters the worker; when the module folder is gone as well (its `module.json` answers 404) the caches and their metadata are deleted first. The count stays in IndexedDB, so a retired worker the browser restarts for a page still open stores nothing.
  - Messages from the page: `config {p2p, timeoutMs, quotaBytes}`, `stats`, `claim`, `put`, `clear`, `abort-preload {urls}`.
- `sw-client.mjs`: `initServiceWorker()` (not awaited by main), `recheckServiceWorker()` (run the registration again, e.g. after the GM put the bridge in place; resolves with the new status), `abortSwPreloads(urls)`, `cleanupServiceWorker()` (unregisters and drops caches when the `serviceWorker` setting is off), `clearDeviceCache() → {freedBytes}`, `swStatus() = {supported, registered, scope, controlling, cachedBytes, cachedFiles, reason?, script, version, outdated, persisted, needsSetup, dataRootCopy}`, `cachedOptimizedUrls()`, `readCached(url)`, `sendSwConfig()`. `dataRootCopy` is what sits at the Data root under the bridge's name: "bridge", "stale" (a full copy of an older `sw.js`, from the 0.1.0 instructions), "missing", or null when not checked. `needsSetup` is true while the local cache waits for the GM: the bridge is not at the Data root (and the server sends no `Service-Worker-Allowed` header), or the file there is a stale copy to replace by the bridge; the UI turns it into the "finish setup" step. The SW message listener is attached at module import (before the first scene draws). Before the module's own copy is registered, a HEAD asks the server whether it sends `Service-Worker-Allowed` for the route root, so a fresh install logs no refused registration on every page load. A running SW of another version sets `outdated` after one update attempt (`registration.update()`, which also compares the script the bridge imports); the GM is told once, either to replace a stale Data-root copy (`Sw.Outdated`) or that something in front of the server hands out an old `sw.js` (`Sw.OutdatedServer`). Persistent storage is requested on Chromium only (Firefox would prompt).
- `swarm.mjs`: `initSwarm()`, `swarmStatus() = {enabled, reason?, peers: [{userId, name, state, rttMs, upBytes, downBytes, bytesPerSec}], up, down, servedFiles, fetchedFiles, failures, lastFailure?: {userId, name, reason, local, remote, at}, banned, tracker?}`, `fetchFromPeers(url, {signal, onProgress, urgent})`, `holderCount(path, excludeId)`, `canSeed(userId)` (coordinator: that user's browser announced itself to the tracker and can serve files right now), `swarmOverview() = {sharing, links, upBytes, downBytes}` (coordinator: the swarm as the players report it; the coordinator's own browser is usually not in it), `noteCached`, `noteEvicted`.
  - **In or out.** `blocker()` gives the first thing that keeps a browser out of the swarm, exposed as `swarmStatus().reason`: `"disabled"` / `"cdn"` (off for the world, or behind a caching CDN: `effectiveNetwork().p2p`), `"notChosen"` (a player who has not answered the first-run card), `"optOut"` (`p2pParticipate` off), `"local"` (the browser runs on the server's own machine, so its upload is the server's upload; a GM anywhere else is a normal peer), `"insecure"`, `"noWebRTC"`, `"noCrypto"`, `"noCache"` (no Service Worker controls the page; P2P only fetches and serves through the worker's cache). A browser that is out opens no peer connection, answers no signaling and announces nothing; it switches live when one of those settings or the page's controller changes. The tracker still runs on the coordinator. For tests with several players on one machine, `localStorage["optimal-foundry.debug.allowLocalP2P"] = "1"` overrides `"local"` per origin.
  - **Tracker** (coordinator, memory only): clients announce every optimized path they cache (`MSG.P2P_HAVE {add, drop, reset?}`, or `{off: true}` when the browser leaves the swarm); the library, `sha256` and `p2pMinFileKB` are checked only at `MSG.P2P_WANT` time, which returns holders ranked by the requester's own measured throughput, else everyone's mean. Self-reported rates for oneself are ignored and rates are clamped to 100 MB/s. The coordinator sends `MSG.P2P_RESYNC` (clients re-announce with jitter) when it starts, when it takes over, and when a user (re)connects. A seeder asked for a file it no longer has drops it from the tracker.
  - **Transport**: native `RTCPeerConnection` with one negotiated DataChannel, ICE servers from `iceServers`, signaling over `MSG.P2P_SIGNAL` (perfect negotiation, per-session ids). ICE timeout 10 s; candidate types are recorded and the last failure is exposed.
  - **Source selection.** Urgent loads (canvas loading or counted urgent loads) use only peers already connected; they warm links for later. After a tracker request times out, the tracker is skipped for 30 s (until the coordinator's next `P2P_RESYNC`). With `navigator.deviceMemory` of 4 or less, files over 128 MB are not fetched from peers. Background loads may wait for ICE, with progress pings to the SW meanwhile. The game never waits on a slow peer: when an urgent load starts on this browser (`optimal-foundry.urgentLoad`) every background download in flight takes the rest of its file from the host, and an urgent download that averages under 256 KB/s over a 2 s window does the same. At most 2 files download at once per page; further misses go to the network.
  - **Transfer.** 1 MiB pieces, up to 3 peers with 2 lanes each, chunks ≤ min(`sctp.maxMessageSize`, 64 KiB), backpressure. A peer answering `busy` (at its upload cap) is dropped for that file at once on an urgent load; a preload lane backs off (400 ms × attempt, 6 attempts, signalling progress to the SW) and asks again. When the peers run out with part of the file delivered, the missing span comes from the host in one Range request instead of the whole file again. Endgame: an idle lane duplicates the oldest piece in flight from a single peer for over 2 s; the first copy wins. The whole file is checked against the library SHA-256; on a mismatch only a lone contributor is struck (3 strikes = banned for the session). A peer that keeps failing is cooled down for 60 s.
  - **Seeding** from Cache Storage, token bucket at `p2pUploadCapMbps` (megabits per second, default 4), at most 3 uploads and 2 per peer, never while the local canvas is loading. `p2pParticipate: false` → neither seed nor fetch.

## UI (`scripts/ui/`, `templates/`, `styles/`)

Dragged by its head (`[data-of-drag]`, buttons excluded) with `setPosition`; the position is written to the client setting `trackerPosition` when a drag ends and read back in `_initializeApplicationOptions`. `trackerCollapsed` shows one compact line: a warning mark while the local cache needs its setup step, the media icon with a short value (conversion progress, files waiting for review, heavy files waiting for the players, queued count, `!` before the welcome screen), one colored dot per connected player (ready, loading, joining/waiting, unknown as a ring, stale faded; tooltip with name and state), a check when everyone is ready, and how many browsers share, plus the expand button; expanded it shows the setup line with a link to the dashboard, the media line (current conversion with progress, review count with a link, waiting for welcome with a link, paused, heavy files waiting with "Convert now", waiting for the network, off, all done), one row per connected non-GM client from `networkStatus().clients` with `upcomingReadiness()` (tiers 0–1) as a bar, state (stale, joining at position 0, queued at position > 0, loading, ready, waiting, unknown when the coordinator has no readiness for that user while tiers 0–1 are not empty) and a tooltip that also says whether that browser is on HTTPS, has the local cache active and can share (`describeHealth`), plus the plan's tier counts and the sharing line from `swarmOverview()` with the reason nobody shares. A non-coordinating GM session says players show up in the coordinating session. **Everyone is ready:** when every connected player holds all tier 0–1 files and the plan names a scene that is not on screen yet, the count turns green with "Everyone is ready for <scene>", and a watch on its own 3 s timer (coordinator only, so it works with the panel collapsed or hidden) shows one notification per scene per session (`readyCue`). `registerTracker()` adds a toggle tool `ofTracker` to the Tokens scene controls (GM only), opens the panel at ready when `trackerVisible` and starts that watch; `setTrackerVisible(bool)` writes the setting, opens or closes it and re-renders the controls.
- `welcome.mjs`: `OptimalFoundryWelcome` (GM only, `standard-form`, shares the Settings layout) opens at ready while `welcomeDone` is false and closes on other GMs when one finishes. Above the form, a part of its own (`setup-slot.hbs`) says when this page cannot convert, cache or share because it is not on HTTPS (`conversionBlocker()`), and shows the finish-setup step; it is re-rendered alone when the local cache's state changes (registration ends seconds after `ready`), so the picks in the form are never reset. The form offers the presets as four radio cards in one row and the three modes of `backfillMode` (review, auto, off), each with one visible line of description and the longer text in a tooltip (the matching preset is preselected; when none matches, nothing is preselected and a "Custom" chip says the current quality values are kept unless a preset is picked), then `optimizeUploads`, `preloadEnabled`, `p2pEnabled` and the tracker as switches with a line each, and `hostUploadMbps`. "Network only" disables the media part. Submit writes the preset plus those values (changed keys only), then `welcomeDone`, then the tracker, and asks for a reload when a `RELOAD_KEYS` setting changed. "Not now" only closes it. `openWelcome()` only brings an open instance to the front (rendering it again would reset the picks).
- `first-run.mjs`: `ConnectionChoice`, the card a player gets once per browser. `needsConnectionChoice()` is true for a non-GM while `connectionChoiceDone` is false and the world shares between players (`effectiveNetwork().p2p`) or preloads (`preloadEnabled`); `registerFirstRun()` opens the card at ready in that case. It asks only about what the world uses: share files with the other players, yes or no, with the sentence that players who share see each other's IP address, and how much to download ahead (`preloadScope`: everything, only this session, nothing). The settings' defaults are preselected (lighter on a data-saver or cellular connection). Saving writes `p2pParticipate`, then `preloadScope`, then `connectionChoiceDone = true` (the answers first: the swarm reads them when it learns the player has chosen). Closing the card without saving leaves `connectionChoiceDone` false, so no peer connection opens, and the card comes back at the next session.
- `connection.mjs`: `ConnectionPanel` ("My connection"), open to every user from the module settings and from a wifi button in the player list's latency/FPS row. It shows this device's local cache (used of quota), whether it shares (connections, up/down) or the reason it does not (`swarmStatus().reason` through labels), preloading with its scope, and the CDN; on a page without HTTPS it says what that blocks. A GM sees the finish-setup step here too; a player only that the game master has not turned on the local cache yet. A player who has not answered the first-run card finds a "Choose" button that opens it, and the two answers stay locked here until then, so the card remains the one place where the first choice is made.
- `lang/pt-BR.json`, `lang/en.json`: keys `OPTIMALFOUNDRY.Settings.<key>.Name|Hint|Choices.<value>` for every setting a window shows, plus UI strings. Both files carry the same key set and the same `{placeholders}`, and every key named in code exists: `test/static.test.mjs` checks it.

## Cross-cutting rules

- No build step. Plain ESM `.mjs`, relative imports. Use `foundry.*` namespaced v14 APIs; no compatibility branches for older generations and no fallbacks for missing libWrapper.
- Never block the UI thread for long: chunk loops, `await` between items.
- Every subsystem fails closed (disables itself with a console warning) instead of breaking the game.
- What needs HTTPS or localhost (conversion, the Service Worker, P2P) is off on a plain HTTP page and says so with one reason; preloading through the HTTP cache, the budget, the join queue and CDN detection work there.
- Static Foundry files (`/scripts`, `/css`, `/lang`, module and system code) are not cached by the SW; owners with Cloudflare can add an edge cache rule for them (README).

## Background optimizer: corrections (0.2.0)

- Stored library entries carry no `original` (readers get it filled in; `getStoredEntry` gives the server's view without pending writes).
- An item is: convert, upload (a same-name file is reused only at the expected size; a HEAD after the upload must show it), a `done` entry queued, then per batch one `flushLibrary()`, a HEAD of each copy and one `rewriteReferences`.
- The crash marker makes a file final after one attempt (not 3). The queue excludes `skipped`, `failed` x3 and `interrupted`.
- Undo works in groups of 20; an entry marked `cleaned` is undone only when its original is back at the recorded size.
- Self-repair: once per session and on a manual Analyze, the optimized copies the documents use are checked by HEAD (4 at a time) and references to a missing copy go back to the original (the automatic check is skipped through a caching CDN).
- Mirrored copies live in `worlds/<id>/optimal-foundry/<original dir>/`; copies already under the Data-root folder keep working where they are. The scan report takes a copy's origin from its library entry and counts Adventure packs as unread.
- Upload timeout is 60 s plus the file size at 1 Mbit/s; 3 upload failures in a row stop the run (`uploadStopped`); a stall watchdog (5 minutes without progress) terminates the worker and counts a failed attempt (`stalled`).
